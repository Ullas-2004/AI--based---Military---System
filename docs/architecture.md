# AegisAI Architecture

## Overview

Three tiers plus an intelligence layer. The browser talks only to Next.js;
Next.js rewrites `/api/*` to Flask, so there is a single browser origin and no
CORS preflight on normal operation.

```text
                    Browser (analyst workstation)
                              |
                              | same-origin HTTPS
                              v
                 Next.js 16 (App Router, React 19)
                   - Server-rendered shell
                   - lib/api.ts: typed client, JWT attach
                   - rewrites /api/* --> Flask
                              |
                              | REST + JSON, Bearer token
                              v
                      Flask API (application factory)
                              |
        +---------------------+---------------------+
        |                     |                     |
   middleware/           services/              routes/
   - auth (JWT)          - vision (YOLO)        - threats
   - roles               - ml (XGBoost)         - predict
   - validation          - llm (Groq)           - assistant
   - audit               - report (ReportLab)   - auth, data
                         - taxonomy  <-- shared vocabulary
        |                     |                     |
        +---------------------+---------------------+
                              |
                              v
                          MongoDB
        users | vision_detections | threat_predictions
        intelligence_reports | audit_logs
```

## Layers

### 1. Presentation — Next.js 16 / React 19

- **App Router**, TypeScript strict mode, Tailwind CSS v4 with design tokens
  declared in `app/globals.css`.
- `lib/api.ts` is the only place that performs HTTP. It attaches the bearer
  token, applies timeouts, normalises errors into `ApiError`, and clears the
  session on 401 so the UI cannot loop on failing requests.
- `lib/use-async-data.ts` handles fetch-on-mount with cancellation, so a slow
  response cannot resolve against an unmounted component.
- `lib/auth-context.tsx` holds session state. Tokens live in `sessionStorage`
  and therefore expire with the browser tab.

### 2. Application — Flask

Built through a `create_app()` factory so tests and WSGI servers construct
isolated instances. Cross-cutting concerns are middleware, not scattered checks:

- **`middleware/auth.py`** — bcrypt hashing, JWT issue/verify with a pinned
  algorithm, `@token_required` and `@roles_required` decorators, audit logging.
- **`middleware/validation.py`** — every caller input is validated before it
  reaches a service. Raises `ValidationError`, which the app converts to a 422
  carrying the offending field.
- **Error handlers** — internal exceptions are logged server-side and replaced
  with a generic message. Stack traces and driver errors never reach a client.

### 3. Intelligence — vision, ML and LLM

Both models load lazily and are cached, so importing a module does not pay the
torch startup cost or fail when weights are absent.

#### The shared taxonomy

`services/taxonomy.py` is the single vocabulary both engines speak. This exists
because the two halves previously disagreed: YOLO emitted COCO names
(`person`, `truck`) while the threat model was trained on military classes
(`Soldier`, `Truck`). The encoder mapped anything unrecognised to index 0 —
`Civilian Car`, the *lowest*-threat class — so a soldier detected near the
border scored MEDIUM.

Now the mapping is explicit, and anything unmapped is **reported, never
guessed**:

```
COCO detection ──> map_detection_class() ──> threat class ──> XGBoost scorer
                          │
                          └─ unmapped ──> surfaced to the analyst
```

> **Operational caveat.** The bundled weights are stock `yolov8n.pt`, trained on
> COCO. COCO contains no tank, UAV or military helicopter class. The mapping is
> a documented *proxy* so the demo pipeline is coherent end to end; every
> detection carries `is_proxy_class: true`. A real deployment requires weights
> fine-tuned on military imagery.

#### Threat model

A gradient-boosted regressor (XGBoost) over six features: object class,
detection confidence, weather, terrain, time of day and distance to border.
Trained on synthetic telemetry generated by a doctrine-inspired scoring function
plus Gaussian analyst noise, so the model learns a noisy interacting function
rather than memorising a handful of if-statements.

Holdout performance: MAE ≈ 3.4 points, R² ≈ 0.96. Every feature carries signal
by construction — confidence scales the whole assessment multiplicatively, and
terrain interacts with object class.

Persisted in XGBoost's native JSON format, which is version-portable and needs
no scikit-learn at inference time.

### 4. Data — MongoDB

Accessed through `database/mongodb.py`, which connects lazily, caches the
handle, and applies a retry cooldown after failure so a downed database cannot
turn every request into a multi-second server-selection timeout.

`get_db()` returns `None` when unavailable, giving every caller one obvious
thing to check. Stateless endpoints keep working; stateful ones return 503.

Indexes are created idempotently on first connection: a unique index on
`users.username`, and descending `created_at` / `timestamp` indexes backing the
"newest N" queries every history view performs.

## Request lifecycle: image detection

```
POST /api/threats/detect  (multipart, Bearer token)
  │
  ├─ @token_required ................ 401 if absent/expired
  ├─ validate_image_upload() ........ 422 on bad extension or magic number
  │                                   413 if over MAX_UPLOAD_MB
  ├─ save to uploads/<uuid>.<ext> ... randomised name, no caller control
  ├─ detect_objects() ............... YOLO inference
  │     └─ map each class through the taxonomy
  ├─ delete the uploaded frame ...... findings persist, imagery does not
  ├─ insert into vision_detections
  ├─ log_audit_event()
  └─ 200 with detections + unmapped list
```

## Security model

| Concern | Control |
| --- | --- |
| Password storage | bcrypt, per-password salt, configurable cost; >72-byte inputs rejected with 400 |
| Session tokens | HS256 JWT, pinned algorithm, required claims, 12h expiry, `sessionStorage` |
| Authorisation | `@token_required` on all data endpoints; `@roles_required` on the audit trail |
| Upload safety | Extension allowlist + magic-number sniff + size cap + randomised names |
| Injection | Retrieved records are delimited as untrusted data in LLM prompts; PDF content is XML-escaped |
| Information disclosure | Generic client errors; identical responses for unknown user vs wrong password |
| Transport | CORS scoped to configured origins; `nosniff`, `DENY`, `no-referrer`, `no-store` headers |
| Misconfiguration | App refuses to boot in production without a ≥32-byte secret, with debug on, or with wildcard CORS |

## Scalability notes

Current shape suits a single-node demonstration. For real load:

- Run under a production WSGI server with multiple workers (`waitress`,
  `gunicorn`). The Flask dev server is single-threaded by default.
- Move YOLO inference to a task queue. It is CPU-bound and multi-second; holding
  a request thread for it does not scale.
- Add a rate limiter on the auth endpoints (`Flask-Limiter` with a Redis
  backend) to blunt credential stuffing.
- Pagination is already enforced server-side with clamped limits, so no single
  request can serialise an unbounded collection.
- The indexes above cover current access patterns; add compound indexes if
  filtering by user or severity is introduced.
